# 開発手順：ソースから作る・直すとき

中身は Rust（WebAssembly にしてブラウザで動かす）、画面は three.js の 3D で、Vite でビルドします。
機能と使い方は `README.md`、ライセンスは `LICENSE` と `THIRD_PARTY_NOTICES.md` にあります。

| 場所 | 中身 |
|---|---|
| `core/` | Rust（crate 名 `typing_core`）。かな → ローマ字・打鍵の判定・スコア・配列・記録・バックアップ・シャトルランの進み方など、画面に関係ない処理。JavaScript から呼ぶ口は `core/src/wasm.rs` |
| `web/` | 画面（HTML・CSS・JavaScript・three.js）。Rust は `web/src/core.js` の包みから使う。3D キーボードは `web/public/models/keyboard.glb`（キーの対応表は `web/src/keyboard_keys.js`）。版番号は `web/package.json` の `version` |
| `golden/` | 旧版 v5 の答え（正解データ）を集める道具。答えは `core/tests/golden/` |
| `tools/` | 3D キーボードを Blender から書き出す道具 |
| `env.sh` / `start.sh` / `check.sh` | 道具の場所の設定 / 手元で開く / まとめて確かめる |
| `toolchain/` | Rust の道具を置く場所（`env.sh` が作る。リポジトリには含めない） |
| `old_versions/` | 旧版 v5 の本体を置く場所（リポジトリには含めない。下の A の 4） |

## A. 準備（最初の 1 回だけ）

1. Node.js（npm を含む。20.19 以降か 22.12 以降）を入れる。
2. Rust の道具を入れる。`env.sh` は、Rust の道具をホームではなく、このフォルダの `toolchain/` に置く設定です。

   ```sh
   . ./env.sh
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --no-modify-path --profile minimal -c clippy,rustfmt -t wasm32-unknown-unknown
   cargo install wasm-pack --locked
   ```

   すでにホームに Rust と wasm-pack が入っていて、そちらを使いたいときは、`env.sh` の `RUSTUP_HOME`・`CARGO_HOME` の行を自分の環境に合わせて書き換えます。
3. npm の部品を入れる。

   ```sh
   (cd web && npm install)                 # three・vite
   npm install && npx playwright install chromium   # ルート：ブラウザでのテスト（Playwright）
   ```

4. （任意）旧版 v5 の本体を `old_versions/` に置く。`check.sh` の 7（v5 のバックアップの引き継ぎ）と、正解データの作り直し（`golden/generate.mjs`）に使います。v5 の本体は、このリポジトリの過去のコミットにあります。

   ```sh
   mkdir -p old_versions
   git show cd7dff7:source/typing_practice_v5.4.5.html > old_versions/typing_practice_v5.4.5.html
   ```

5. （任意）自分のパソコンだけの設定は、ルートに `env.local.sh` を作って書きます（`env.sh` が読み込みます。リポジトリには含めません）。

   ```sh
   export PATH="/path/to/node/bin:$PATH"          # Node が特別な場所にあるとき
   export CHROMIUM_PATH=/path/to/chrome           # Playwright が入れたものとは別の Chromium でテストするとき
   export KEYBOARD_BLEND=/path/to/keyboard.blend  # 3D キーボードの元（F）
   export BLENDER=blender                         # Blender のコマンド（F）
   ```

## B. 動かす

- 手元で開く：`bash start.sh`（足りない部品を用意して、ブラウザで開きます。止めるときは Ctrl+C）
- 画面だけ変えたとき：先に `. ./env.sh && (cd core && wasm-pack build --target web)`、あとは `cd web && npm run dev`
- 配るファイルを作る：`cd web && npm run build` → `web/dist/`。サーバーに置いて開きます（ファイルを直接開く形では WebAssembly を読み込めません）
- GitHub Pages など、どのフォルダに置いても動くように、読み込みは相対パスにしてあります（`web/vite.config.js` の `base: './'`）

## C. コードを変えたとき

1. 下の G で版番号を決め、`web/package.json` の `version` を書き換える（画面の版番号もここから作られます）
2. コードを直す
3. ルートで `bash check.sh` を実行し、全部合格するまで直す。中身は次の順です
   1. Rust のテスト（旧版 v5 から取った正解データ約 8 万件との照らし合わせ）
   2. clippy・rustfmt（書き方と書式。書式が違えば `cargo fmt` で直す）
   3. WebAssembly のビルド（`core/pkg/`）
   4. WebAssembly の口（`web/api_test.mjs`）と、壊れた入力で Rust が止まらないか（`web/fuzz_test.mjs`）
   5. 3D のキーの対応表と、画面のビルド（`web/dist/`）
   6. ブラウザでの通し確認（`web/smoke_test.mjs`。各画面の操作・エラーなし）
   7. データの引き継ぎ（`web/v5_backup_test.mjs`。v5 のバックアップを復元し、逆向きも確かめる。v5 の本体がなければ飛ばす）
   8. 配るファイル（`web/dist/`）に、ビルドしたパソコンのパス・ユーザー名が入っていないか
4. 機能が変わったら `README.md` も直す

守っていること：

- Rust の計算の答えは旧版 v5 と同じにしてあります。わざと変えるときは、`core/tests/golden_*.rs` の照らし合わせも理由を書いて直します。時刻と乱数は Rust の中で取らず、引数で受け取ります
- Rust に口を足したら `core/src/wasm.rs` → `web/src/core.js` → `web/api_test.mjs` の 3 つを直します（包みの関数にテストがないと `api_test` が失敗します）
- 保存データの形（localStorage のキーと中身）は v5 と同じです。v5 のバックアップを読めること、v5 が v6 のバックアップを読めることを `v5_backup_test.mjs` で確かめています
- 通信は Google Fonts と kuromoji の辞書の 2 つだけです（kuromoji は SHA-256 が一致したときだけ使う）。three.js などは npm でまとめて配り、CDN から読みません。Content-Security-Policy はビルドしたページに `web/vite.config.js` が入れます
- Rust のビルドは、WebAssembly にパソコンのパスを埋め込まないよう、`env.sh` の `RUSTFLAGS` でパスを置き換えています
- 保存データの名前など、外から来る文字を項目名に使う入れ物は `Object.create(null)` か `Map` にします

## D. 見た目を確かめる

`cd web && node scripts/shot.mjs --url '?q=high' --wait 3000 --shot 写真.png`（使い方はファイルの先頭）
GPU のないヘッドレスのブラウザでは、自動で「軽い表示」になります。普通の表示を撮るときは `?q=high` を付けます。
ソフトウェア描画では、写真に横の帯などの乱れが出ることがあります（本物のブラウザでは出ません）

## E. うまくいかないとき

- `cargo` や `wasm-pack` が見つからない：`. ./env.sh` を読み込んだか確かめる
- フォルダを動かしたあと、最初の `check.sh` は Rust を作り直すので数分かかる
- `npm` が見つからない：Node.js を入れるか、`env.local.sh` で PATH に足す

## F. 3D キーボードを作り直すとき

元の Blender のファイル（`.blend`）はリポジトリに含めていません。書き出したもの（`web/public/models/keyboard.glb`）を使っています。
`.blend` があるときは、`bash tools/export_keyboard.sh keyboard.blend の場所`（または `KEYBOARD_BLEND`）で glb に書き出します（Draco 圧縮。キーは `Key_<名前>` の別々の物体、親は `KB_Root`。`.blend` は保存しません）。
キーの名前を変えたら `web/src/keyboard_keys.js` も直し、`check.sh` の 5 で確かめます

## G. 版番号（セマンティックバージョニング）

版番号は `web/package.json` の `version` に書き、git のタグ（`v6.0.2` など）で残します

- MAJOR：互換性がなくなる変更（前の版のバックアップ・保存データを引き継げない、機能の削除、作りを大きく変える）
- MINOR：互換性のある機能の追加・拡張
- PATCH：機能を増やさない修正（バグ、文言、見た目、速さ）
- 上げた番号より右は 0 に戻す。複数の変更があるときは、いちばん大きい種類で上げる
- README・開発手順・テスト・道具のスクリプトだけを変えたときは、番号を上げない
